3. Problem Statement, Objectives, and Prototype Scope

Problem Statement: Nano- and pocketqube-class satellites operate under severe SWaP-C constraints. During short ground-station passes (5–10 minutes), multiple subsystem streams (TT&C beacons, Codec2 audio, M17 data packets, heavy SSTV imagery, and housekeeping logs) compete for a single shared RF downlink. Without OS-level process scheduling, thread synchronization, memory virtualization, and cache management, low-priority tasks starve, buffer overflows drop critical telecommand acks, and memory boundary violations jeopardize mission survivability.

Project Objectives

  • Downlink Preemption & Starvation Prevention: Implement preemptive priority scheduling where emergency TT&C telemetry immediately preempts bulk transfers, with aging ensuring heavy SSTV image completion before horizon loss.
  • Thread-Safe Telemetry Concurrency: Implement multi-threaded producer-consumer synchronization with mutex locks and condition variables, ensuring zero telemetry frame drops between EPS, OBC, COMM, and the downlink transmitter.
  • Fault-Tolerant Memory Virtualization: Simulate paging MMU address translation and segmented memory boundary checks to protect safety-critical flight sequences from amateur payload segmentation faults.
  • Constrained Cache Optimization: Model LRU buffer cache replacement under strict onboard RAM budgets (16 KB RAM) to minimize page-fault penalties during rapid orbital passes.

EXPERIMENT 06: CPU SCHEDULING WITH AGING

6. Experiment 06: Preemptive Priority CPU Scheduling with Aging

Aim: To simulate Preemptive Priority CPU Scheduling with dynamic Aging using an AI-enabled satellite downlink use case (SomaiyaSat).

Use-Case Connection: The shared RF transmitter represents the CPU core. Downlink tasks represent incoming processes with varying urgencies. Aging prevents high-volume, lower-priority payload tasks (SSTV Earth Observation images) from starving during heavy telemetry traffic.

Mathematical Formulas & Aging Mechanism

  • Turnaround Time (TAT) = Completion Time (CT) − Arrival Time (AT)
  • Waiting Time (WT) = Turnaround Time (TAT) − Burst Time (BT)
  • Response Time (RT) = First CPU Execution Time − Arrival Time (AT)
  • Aging Rule: For every 3 consecutive time units a ready process waits in the queue, its effective priority decreases by 1 (numerical decrease = urgency increase): effPriority = effPriority − 1, bounded at floor = 2 so critical TT&C beacons (Priority 1) are never overtaken.

EXPERIMENT 07: PROCESS & THREAD SYNCHRONIZATION

7. Experiment 07: Bounded-Buffer Producer-Consumer with Mutex

Aim: To implement classical process and thread synchronization using Mutex locks and Condition Variables for SomaiyaSat's multi-subsystem telemetry stream.

Use-Case Connection: In SomaiyaSat, three independent onboard sensor subsystems—Electrical Power System (EPS), Onboard Computer (OBC), and Communications (COMM)—periodically sample hardware state and produce packets into a shared ring buffer. The RF Downlink transmitter consumer thread reads and transmits packets over the amateur radio carrier. Synchronization prevents buffer overflow, underflow, and race conditions.

C++ Synchronization Architecture

// Circular Bounded Buffer Synchronization Primitives: const int BUFFER_CAPACITY = 4; queue<TelemetryPacket> bufferQueue; mutex mtx; condition_variable notFull; // Signaled when slot becomes available condition_variable notEmpty; // Signaled when telemetry packet is buffered // Producer Thread (Sensors): unique_lock<mutex> lock(mtx); notFull.wait(lock, []() { return bufferQueue.size() < BUFFER_CAPACITY; }); bufferQueue.push(pkt); lock.unlock(); notEmpty.notify_one(); // Consumer Thread (RF Downlink Transmitter): unique_lock<mutex> lock(mtx); notEmpty.wait(lock, []() { return !bufferQueue.empty(); }); TelemetryPacket pkt = bufferQueue.front(); bufferQueue.pop(); lock.unlock(); notFull.notify_one();

EXPERIMENTS 08 & 10: MEMORY MANAGEMENT & LRU

8. Experiment 08: Memory Management (Paging & Segmentation MMU)

Aim: To simulate memory management schemes (Paging address translation and Segmentation bounds protection) for the SomaiyaSat onboard flight computer.

Use-Case Connection: SomaiyaSat's micro-controller possesses limited RAM. Safety-critical firmware (SomaiyaPod burn-wire deployer routines) must be strictly isolated from user payload tasks (M17 packet buffers, SSTV cache). Paging eliminates external fragmentation, while segmentation provides memory protection.

9. Experiment 10: Virtual Memory LRU Page Replacement Algorithm

Aim: To implement the Least Recently Used (LRU) page replacement algorithm and evaluate hit/miss ratios under constrained satellite memory frames.

Use-Case Connection: During ground-station line-of-sight passes, the transmitter repeatedly requests data tiles and audio packets. An efficient LRU cache retains frequently accessed TT&C beacon headers while evicting stale tiles.

11. Limitations and Future Scope

  • Hardware Footprint Constraints: Current simulations assume POSIX multi-threading, whereas bare-metal flight micro-controllers (STM32 / FreeRTOS) require lightweight RTOS task queues and fixed-block heap allocators.
  • Static Aging Step: Aging step was fixed at delta t = 3s. Future work will implement dynamic AI-driven aging steps tied to real-time orbital elevation angles and ground pass remaining time.
  • Doppler Frequency Shifts: Future versions can integrate RF link quality degradation metrics (Doppler frequency offset and variable baud rates) directly into the priority scheduling weight calculation.
